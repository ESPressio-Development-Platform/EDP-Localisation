# Historical ContractFamily archive (G5 incremental)

EDP-Localisation tooling owns generated ContractFamilies, their semantic fingerprint, EDPL v1 pack parsing, per-output SHA256, canonical build manifest, and generated C++ contract. **This tranche reuses all of those owner facilities**, without copying or reimplementing the format in EDP-Logging.

The opt-in Python `tools/edp_localisation/historical_archive.py` publishes a complete internally verified generated set under `<archive>/families/<64-uppercase-hex ContractFamilyDigestSha256>/`. The original `localisation-build-manifest.json`, `GeneratedLocalisationContract.hpp`, `GeneratedLocalisationIdentifiers.hpp` and all `packs/<canonical-language>.edploc` files are retained byte-for-byte. The 128-bit `ContractFamilyFingerprint` is the prefix of the canonical 256-bit semantic digest. The owner verifier checks manifest structure, recorded output hashes, parser CRC32C, embedded language and fingerprint. `archive_generated_family(generated,archive)` refuses source symlinks, fail-closes on corrupt previous archive entries, performs a staging copy followed by verification, then publishes the directory. Repeating publication with exact bytes is idempotent; an altered existing family is rejected, never overwritten.

`open_historical_family(archive, fingerprint, digest=...)` verifies all archived families, resolves the exact 128-bit recorded fingerprint (optionally pinned to the whole digest), rejects missing/ambiguous/corrupted entries, then yields the *existing* `GeneratedContractFamily` parser/resolver with ordinary language/type/fallback operations. Separate snapshots with different semantic fingerprints preserve independent language and identifier presentations; they do not retroactively change old records. CLI: `PYTHONPATH=tools python3 -m edp_localisation archive-family --generated generated/localisation --archive historical/` and `PYTHONPATH=tools python3 -m edp_localisation verify-archived-family --archive historical/ --fingerprint <32 uppercase hex> [--digest <64 uppercase hex>]`.

**This proves local file integrity, not provenance or authenticity.** The manifest's full canonical digest/fingerprint and SHA256 files may be self-consistent but attacker-created. The publisher must obtain/trust the authoritative historical generated set (e.g. an authenticated pinned release) before archival. Unlike `verify_generated_set`, historical verification must *not* compare bytes with the present/latest semantic source: it deliberately retains old versions. The toolchain version recorded in the archived manifest must still be supported by this version of `verify_internal_generated_set`; archival migration for earlier toolchains is not claimed. No stable remote service, signature registry, tamper-proof medium, field-by-field LogRecord representation, Flash sink or end-to-end runtime historical resolver is implemented.

This is an **offline CLI/tooling** facility, not MCU runtime code and not a new EDP dependency. It does not create a TypeIdentifier or address G4's governed authority allocation.

**Durable local publication (2026-10-16 tranche):** the publisher acquires an exclusive nonblocking POSIX `flock(LOCK_EX|LOCK_NB)` on the stable never-unlinked `<archive>/.publisher.lock` inode and reports `ToolError` if another cooperating writer owns it. It `fsync`s that archive root, then each complete generated file, every nested staging directory, the staging root and the final family parent directory after its atomic same-filesystem rename. Only after the final directory persistence barrier does it report `Archived`. Its idempotent `AlreadyArchived` path compares every expected source/output file and verifies the existing family. Unexpected/corrupt archives, symbolic links and collisions fail closed. An interrupted `.stage-*` remains invisible to lookup and is removed after an ordinary caught failure; after a hard crash a left-behind stage is still ignored and requires operator cleanup. Competing cooperating publishers do not wait forever.

**Boundaries:** this is host POSIX-filesystem durability under the operating system's `fsync`/rename guarantees; it cannot force an untrustworthy disk controller to honor flushes or resist privileged writers that ignore advisory locks. Callers must supply a trusted root and prevent hostile path replacement between validation/copy. A hard crash **after the atomic rename but before the final directory sync** may leave a valid published family although the call did not report success; retry/reopen must verify by canonical digest and never silently overwrite. It provides neither signed publisher provenance nor embedded flash wear/retention/power-fail guarantees, native MCU runtime lookup, portable Windows locking, network-filesystem lock reliability or migration of older manifests. Fail closed where POSIX `flock` is unavailable.


Tests `tools/tests/test_historical_archive.py`: genuine generated Localisation source fixture, two semantic generations with different historical language values, exact replay after source deletion, idempotent publish, altered binary pack/CRC failure, fingerprint/digest mismatch and symbolic-link rejection. Full Localisation Python suite, host C++ contracts and downstream Logging generated-schema tests must be rerun for each source change. All package versions frozen at `0.1.0`.
